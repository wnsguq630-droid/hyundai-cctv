확인된 원인
점검 시 운영 HTML은 hyundai-cctv-deploy/index.html과 정확히 일치했습니다.
이 페이지에는 상담 시안용 inline onsubmit이 남아 있고 외부 script 로딩이 없었습니다.
루트 index.html과 script.js는 Firebase 연결본이지만 운영 페이지에는 사용되지 않았습니다.
Vercel 프로젝트 설정은 직접 읽지 않았으므로 실제 Root Directory / Output Directory 값은 확인이 필요합니다.

코드 변경
- hyundai-cctv-deploy/index.html: 시안 submit 제거, 기존 폼에 id/name/검증 속성 추가, 상태 메시지 및 숨김 honeypot 추가, module script 로딩.
- hyundai-cctv-deploy/script.js: 현재 루트 Firebase 처리 코드를 연결.
- script.js, hyundai-cctv/script.js: 동의 체크값 사용, handler 재연결 방지, getApps 기반 앱 재사용, 기존 자유 입력 카메라 수 지원.
- firestore.rules: 9개 필드 유지, 자유 입력 카메라 수 1~30자 허용, 추가 명시적 타입 검증.
- 이 안내 및 hyundai-cctv-deploy/README.txt: 적용 순서 수정.
HTML의 기존 스타일, 화면 문구, 이미지, 레이아웃, 전화/견적/결합상품 UI는 유지합니다.
카카오톡 및 이용약관의 기존 클릭 코드는 상담 submit과 무관하므로 유지합니다.
각 페이지의 스크립트를 해당 폴더에 함께 배포해야 합니다.
기존 hyundai-cctv 폴더의 Supabase 안내/SQL은 과거 자료이고 실제 전송 JS에는 더 이상 사용하지 않습니다.

저장 필드 (정확히 9개)
name, phone, placeType, location, cameraCount, message, privacyAgreed, status, createdAt
전화번호는 숫자만 저장합니다.
privacyAgreed는 실제 체크값이며 true인 경우에만 전송됩니다.
status는 신규, createdAt은 serverTimestamp()입니다.
운영 구버전 폼에는 문의내용 입력이 없으므로 기존 결합상품 체크 선택을 message에 저장합니다.
기존 문의내용 입력이 있는 페이지에서는 해당 입력을 message에 저장합니다.
추가 필드를 보내지 않습니다.

Firebase Console에서 직접 게시해야 하는 Firestore Rules
자동 적용 구조가 아닙니다.
저장소에는 Firebase 설정(firebase.json/.firebaserc), CLI 배포 스크립트 및 GitHub Actions 규칙 배포 워크플로가 없습니다.
Vercel 정적 사이트 배포나 GitHub 파일 변경만으로 Rules가 게시되지는 않습니다.
1. https://console.firebase.google.com/project/hyundai-cctv-24280/firestore
2. (default) 데이터베이스를 선택하고 Rules 탭 열기.
3. 이 프로젝트 루트의 firestore.rules 내용을 전체 복사하여 게시.
4. 게시 성공을 확인한 뒤 아래 실사용 테스트 진행.
외부에 별도 자동화가 있는지는 확인하지 않았습니다.
실제 Console 현재 규칙은 읽거나 수정하지 않았습니다.
